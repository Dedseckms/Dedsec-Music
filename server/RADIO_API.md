# Персональное радио

Маршруты находятся под существующим profile prefix. Авторизация — подтверждённый
native Navidrome JWT в Bearer header. Публичной регистрации нет.

`POST /dedsec/profile/v1/radio/mix`

```json
{"mood":"ANY","mode":"BALANCED","size":40,"history":[],"dislikedIds":[],"excludeIds":[]}
```

- mood: ANY, ENERGY, CHILL, FOCUS, WORKOUT, PARTY, SAD, HAPPY.
- mode: BALANCED, FAVORITES, DISCOVERY.
- size:1–60. history: до200 `{id,playedAt,count}`, playedAt в epoch milliseconds.
- dislikedIds: до1000 ID, excludeIds: до100 ID. Вход до64KiB, ответ до512KiB.
- Ответ: `{songs:[OpenSubsonicSong],analysis:{indexed,total},reason:null|"ANALYZING"|"NO_MATCHES",mood,mode}`.

Подбор ранжирует всю доступную этому пользователю библиотеку. Избранное и история
берутся из его собственных annotations, пользовательских событий и переданной
истории. FAVORITES выбирает строго его избранное; DISCOVERY понижает знакомые
записи. Исключённые/непонравившиеся и недавно прозвучавшие треки подавляются,
соседние исполнители по возможности различаются. Небольшая вариация применяется
только к близким оценкам; пользовательские предпочтения важнее этой вариации.

Настроения используют строгую пригодность по измеренным признакам, для FOCUS,
PARTY, HAPPY и SAD также по жанрам. Это приближение по звучанию/метаданным, без
распознавания смысла текста или эмоционального состояния. Неподходящие записи
не добавляются для заполнения размера. Пока нужные файлы не проанализированы,
возможна короткая/пустая очередь с ANALYZING. Отсутствие подходящих после анализа
обозначается NO_MATCHES. ANY может работать по метаданным до окончания анализа.

`POST /dedsec/profile/v1/radio/events`

```json
{"id":"song-id","kind":"skipped","positionMs":10000,"durationMs":180000}
```

kind: played/skipped/disliked. Ответ `{ok:true}`. Проверяется доступ пользователя
к треку. Для оценки пропуска/завершения используется настоящая длительность из
каталога. Очень ранний пропуск и конец записи не считаются отрицательным сигналом.
Повтор одного события в течение30 секунд не увеличивает счётчик. Disliked —
постоянное исключение для этого пользователя; чужие события не учитываются.
События радио не переписывают native избранное и не подменяют обычный scrobble.

Каталог читается из Nav SQLite в режиме read-only/query-only с ограничением
времени запроса; видимость задаётся user_library, жанры — tag/media_file_tags.
Ни схема, ни данные Nav не меняются. Индекс и feedback — отдельные private SQLite.

Одновременно работает один анализатор. FFmpeg читает20-секундный фрагмент,
вычисляются RMS, spectral centroid/flux, zero-crossing и tempo/confidence через
автокорреляцию огибающей. Нет NumPy или внешнего worker. Ограничения: nice19,
один CPU/thread, CPU5s/wall15s, writable data128MiB, bounded output, только
file/pipe protocols; дочерний процесс прекращается при смерти родителя.
Индекс keyed по физическому пути, mtime, размеру и версии алгоритма. Симлинки и
выход за корень библиотеки отвергаются. Файлы музыки не изменяются.

Worker уступает загрузкам через общий slot, приостанавливается при load>0.8,
резерве менее10GiB или наличии `data/api/radio/analysis.pause`. Между извлечениями
пауза минимум5 секунд и не меньше четырёх длительностей работы. Межпроцессный
lock исключает два фоновых анализатора. После перезапуска индекс продолжается.

В generic Compose API получает каталог Nav только read-only: NAV_DB_PATH и
RADIO_LIBRARY_MAP связывают ID библиотеки с физическим каталогом API. Для иной
структуры задайте эту явную карту; пути из клиентского запроса не принимаются.
