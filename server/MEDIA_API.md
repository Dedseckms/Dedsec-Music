# Единый вход, загрузки и тексты

Все новые маршруты используют тот же проверяемый Navidrome Bearer JWT на
музыкальном HTTPS origin. Пароль и JWT не передаются внешнему поставщику текстов.
Новый слушающий порт и отдельный сервер не нужны. Старые совместимые upload/login
маршруты продолжают работать.

## Возможности и загрузка

`GET /dedsec/profile/v1/capabilities` после авторизации:

```json
{"schema":1,"uploads":{"mode":"navidrome","path":"/dedsec/profile/v1/uploads"},"lyrics":true}
```

`POST /dedsec/profile/v1/uploads?path=%2Ffilename.mp3` — сырое тело файла с тем же
Bearer JWT. Принимается только параметр `path`, один безопасный basename.
Возвращается существующий ответ загрузки:

```json
{"status":"accepted","name":"filename.mp3","bytes":12345,"duration":120.5}
```

Ограничения общие с прежним uploader: **100000000 bytes**, до **1200 секунд**,
настоящее аудио по ограниченному FFprobe, обложка attached_pic разрешена,
настоящее видео запрещено. Учитываются фактические байты, в том числе при chunked
HTTP. Не допускаются traversal, перезапись, удаление или обход валидации для
администратора. Приватный staging и атомарная публикация используют общий upload
semaphore; перед публикацией повторно проверяются текущий аккаунт и отзыв доступа.
Общий запас свободного места — 10 GiB. Новые файлы появляются после штатного scan
Navidrome, как и ранее; ID существующих треков и плейлисты не изменяются.

## Тексты

`GET /dedsec/profile/v1/lyrics/{songID}`:

```json
{"status":"ready","synced":true,"lines":[{"startMs":1200,"text":"Source lyric line"}],
 "source":"LRCLIB","revision":"sha256"}
```

Состояния: `pending`, `ready`, `not_found`, `instrumental`, `error`. Для обычного
текста `synced=false`, у каждой строки `startMs=null`. В `pending/not_found/error`
строк нет, revision пустая. Для ready/instrumental revision — стабильный SHA256
содержимого. Тексты и времена не генерируются, таймкоды берутся только из источника.

Авторизация и доступ пользователя к библиотеке/треку проверяются **перед** cache.
Ключ включает точный song ID, scanner metadata и физические size/mtime файла.
Небезопасные пути, симлинки и отсутствующие файлы не открываются. Замена аудио или
обновлённые scanner metadata создают новый ключ; результат старой задачи не
публикуется поверх новой версии. Есть запросный лимит 60 в минуту на пользователя.

GET не ищет текст в интернете. При cache miss он ставит задание в ограниченную
очередь и сразу возвращает pending. Один фоновый worker сначала вызывает штатный
Navidrome `getLyricsBySongId` через JWT в POST body: это покрывает встроенные и
индексированные sidecar-тексты. Источник ответа называется `Navidrome`, потому что
этот API не сообщает различие embedded/sidecar. Plain lyrics сохраняют пустые
таймкоды; synced lyrics сохраняют исходные миллисекунды и offset.

Далее используется только фиксированный HTTPS API [LRCLIB](https://lrclib.net/docs).
Запрос содержит title/artist/album/duration, поэтому эти метаданные передаются
поставщику. OAuth, аккаунты, JWT, локальные пути и аудиофайлы не передаются.
Точное совпадение title/artist и длительности с допуском 2 секунды обязательно.
Регистр, Unicode compatibility и пробелы нормализуются; qualifiers live/remix/
remaster/sped-up не удаляются. Album подтверждает запись. Если album пуст или не
совпадает, bounded search разрешает только единственного кандидата с точной
оставшейся сигнатурой; неоднозначность возвращает not_found.

Синхронные строки читаются из исходного LRC, повторные строки и таймкоды
сохраняются. При отсутствии реальной синхронизации возвращается обычный текст.
Каждая сеть имеет timeout, лимит тела 256 KiB и срок чтения; перенаправления
запрещены. Обрабатываются не более 32 search candidates, 2000 строк и 128 KiB
нормализованного JSON. Между заданиями — пауза 500 ms, HTTP 429 задаёт общий
Retry-After cooldown. Сетевая ошибка даёт error и повторную попытку позже,
а не выдуманный текст.

Очередь ограничена 32 заданиями, credentials находятся только в RAM и очищаются
после обработки. Задания старше 120 секунд отбрасываются; следующий GET может
повторить lookup. После перезапуска нет сохранённых JWT: lazy запрос пользователя
заново ставит задачу. Native lyrics/ready/instrumental кешируются на 7 дней,
not_found — на 6 часов, error — на 5 минут. Кеш ограничен 2048 записями и 64 MiB
содержимого; файлы вне scan root, доступа к Navidrome DB на запись нет.

Полного анализа библиотеки не производится. Загруженные вручную песни после scan
обрабатываются тем же способом. Сеть lyrics worker не участвует в воспроизведении,
радио, загрузке аудио или ответе lyrics GET.

Проверки: общий `python -m unittest discover -s tests` и отдельный изолированный
`tests/check_native_lyrics.py --binary <Navidrome0.64.2> --parent <private-fixtures>`.
Native fixture создаёт собственный временный аккаунт/библиотеку, проверяет реальный
sidecar и точные timestamps через штатный JWT POST. Установленные аккаунты не
используются.

Формат native lyrics: [OpenSubsonic getLyricsBySongId](https://opensubsonic.github.io/docs/endpoints/getlyricsbysongid/).
