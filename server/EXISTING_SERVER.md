# Подключение к уже работающему серверу

Этот комплект не следует запускать поверх чужой установки командой start.py.
Порты80/443 могут быть заняты, учётные записи и пути могут отличаться. Здесь
приведён аддитивный план для администратора, без автоматического изменения служб.

1. Прочитайте действующие ограничения сервера. Зафиксируйте версии Navidrome,
   путь музыкальной библиотеки, ID библиотеки, локальный адрес native API,
   текущие proxy matchers и процесс, обслуживающий API профилей/загрузок.
   Не читайте пароли, хэши пользователей, OAuth или полные secret-конфигурации.
2. Сохраните согласованные online SQLite-бэкапы Navidrome, старого загрузчика и
   нового журнала импорта, если он уже есть. Проверьте quick_check и SHA256.
   Скопируйте только затрагиваемые скрипты/proxy-фрагмент и их права в приватную
   папку backup. Зафиксируйте конфигурацию процесса и способ отката.
3. Установите закреплённые зависимости в **новое изолированное** окружение, не
   меняя системный Python и зависимости работающих служб. Проверьте API-модули
   и тесты с временными папками. MusicFolder менять не нужно. Новая музыка
   должна публиковаться внутри существующего scan root, staging — снаружи.
4. Если есть старые source ID, выполните seed dry-run по проверенному music-only
   manifest. Seed применяют при остановленном **новом importer worker** либо до
   его первого запуска; действующий старый загрузчик не должен параллельно
   писать те же source ID. Аудио не перемещают. Совпадение названий не используют.
5. Существующий gateway может делегировать только `/dedsec/import/v1/` модулю
   `yandex_import.dispatch(handler, manager)`. Manager требует приватный STATE_ROOT,
   STORAGE_ROOT с физическими `library` и `staging`, native profile.authenticate /
   profile.native, result(status, JSON) и одно общее audio.UPLOAD-ограничение.
   Для другой структуры нужен небольшой явный adapter путей, а не симлинки.
   `IMPORT_LIBRARY_ID` должен совпадать с реальным ID доступной библиотеки.
6. Если HTTPS-прокси уже направляет **весь** `/dedsec/*` к этому gateway, новый
   matcher не нужен. Если он направляет только `/dedsec/profile/v1/*`, добавьте
   ровно `/dedsec/import/v1/*` к тому же upstream. Новые публичные порты не нужны.
   Candidate сначала адаптируют и валидируют; сравнение должно подтвердить, что
   прочие host/routes/upstreams/порядок обработчиков не изменены.
7. Перед активацией дождитесь отсутствия активных загрузок. Если необходим
   перезапуск gateway, останавливают только доказанно его собственный child,
   сохраняя Navidrome, загрузчик, другие службы и supervisor. Способ graceful
   reload/respawn определяется существующим supervisor; universal kill-команды нет.
   Отдельно проверьте загрузку модулей при следующем старте без изменения чужих служб.
8. Проверки после активации: здоровье localhost/HTTPS/TLS,401 без credentials,
   отсутствие изменений существующих сервисов, вход существующим Nav аккаунтом
   в клиенте. Нативный JWT и Yandex OAuth пользователь вводит сам; оператор их
   не извлекает. Тест с реальным источником должен отличаться в отчёте от fixtures.

Откат: запретить новые задачи через прежний proxy-фрагмент, остановить только
новый worker/gateway согласованным способом, вернуть собственные скрипты и
валидированный фрагмент, проверить health. Не восстанавливать старую SQLite БД
поверх живого импорта, не удалять готовое аудио и пользовательские плейлисты.
Журнал и seed-бэкапы сохранить для возобновления. После рестарта незавершённые
задачи требуют нового явного OAuth; автоматическое извлечение токена не предусмотрено.
