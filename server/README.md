# Свой сервер DedSec Music

Комплект запускается отдельно от других приложений. Нужны Linux, Docker Engine с
Compose v2, Python 3.11+, домен с DNS-записью на сервер и доступные снаружи TCP 80/443.
В комплекте Navidrome 0.64.2, Caddy 2.11.9 и API загрузок, профиля и переноса музыки.
Образы закреплены по версиям; Pillow 13.0.0 — по версии и SHA256 для amd64/arm64.

## Первый запуск

1. Скопируйте эту папку в новый каталог, например `~/dedsec-music-server`.
2. Скопируйте `.env.example` в `.env`. Укажите свой домен, email, уникальное имя
   проекта и числа из `id -u` / `id -g`. Запускайте от обычного пользователя с
   разрешённым доступом к Docker. Пароли в `.env` не нужны.
3. Выполните `python3 start.py` в этой папке. Введите логин администратора и
   пароль скрыто в терминале. При ошибке создания/проверки администратора публичный
   прокси остаётся выключенным; локальные службы можно оставить и повторить запуск.
4. Откройте `https://ваш-домен`. В клиенте укажите этот же адрес для музыки,
   профиля и загрузок. В настройках загрузки явно введите тот же логин и пароль.

Скрипт проверяет Compose, место и свободные порты. Он не устанавливает Docker,
не останавливает чужие приложения и не изменяет настройки системы. Если80/443
заняты другим веб-сервером, запуск остановится. Для такой машины нужен отдельный
план интеграции с имеющимся HTTPS-прокси; этот комплект его автоматически не меняет.
До настройки администратора Navidrome/API опубликованы только на127.0.0.1:14533
и127.0.0.1:18083. Не пробрасывайте эти порты наружу. Даже прямой запуск Caddy
из Compose откажется работать без локального `owner.ready`.

## Музыка и аккаунты

Вся общая музыка хранится в `data/music/library`. Navidrome имеет к ней только
чтение; API публикует проверенные загрузки туда. Можно также локально скопировать
свою готовую библиотеку в этот каталог. Сканирование выполняется каждые5 минут.
После загрузки клиенту нужно обновить библиотеку. Веб-интерфейс — стандартный
Navidrome; произвольного файлового менеджера и браузерных операций записи нет.

В приложении откройте **Настройки → Пользователи и их загрузки** под аккаунтом
администратора. Здесь можно создать обычный аккаунт, посмотреть добавленную им
музыку и удалить пользователя, сохранив общую аудиотеку. Новый логин и пароль
подходят для музыки и загрузок. [Ограничения и API администрирования](ADMIN_API.md).

Из терминала обычный пользователь также создаётся командой:

```bash
python3 create-user.py --username friend
```

Новый пароль и пароль администратора вводятся скрыто. Новый пользователь получает
все текущие музыкальные библиотеки, может слушать/скачивать треки и загружать свои
файлы. Приватные плейлисты владельца недоступны ему на сервере, а собственные
плейлисты он создаёт отдельно. Если у владельца есть публичные списки, скрипт
попросит сначала сделать их приватными. До создания пользователя сохраняется
согласованная копия БД. Повторное имя не перезаписывается; если создание прервалось,
проверьте обычный аккаунт и его библиотеки в панели администратора Navidrome.

## Ограничения загрузок

Для всех, включая администратора: максимум **100 000 000 байт (100MB)** и
**1200 секунд (20 минут)** на файл. Считаются фактически принятые байты, включая
chunked-запросы. FFprobe проверяет настоящее аудио, контейнер и конечную известную
длительность. Обложка внутри MP3/FLAC допустима; обычное видео, архивы и исполняемые
файлы не публикуются. Одна проверка выполняется одновременно, с ограничениями CPU,
памяти, времени и вывода. На диске сохраняется резерв10GiB.

Промежуточный файл находится за пределами библиотеки. После проверки он атомарно
публикуется в пользовательской UUID-папке с отдельной UUID-папкой загрузки и
исходным безопасным именем. Чужой файл не перезаписывается. Незавершённые и
отклонённые загрузки не индексируются. Не копируйте папку `staging` в библиотеку.

Аватары принимаются только для текущей подтверждённой учётной записи: JPEG/PNG/WebP
до5MB, до4096 пикселей по стороне и16 миллионов пикселей всего, без анимации.
Отдельный процесс создаёт512×512 JPEG без метаданных. Изображения хранятся вне
музыкальной библиотеки; токены и пароли API не сохраняет.

## Резервная копия и восстановление

```bash
python3 backup.py
python3 backup.py --with-music
```

Первая команда сохраняет согласованные SQLite-копии Navidrome и журнала импорта
через online backup API, проверяет `quick_check`, сохраняет аватары и локальный
marker администратора. Файлы WAL/SHM не копируются поверх согласованной БД.
Когда Caddy работает, его TLS-данные также попадают в приватный архив. Вторая
команда дополнительно копирует всю музыку и может потребовать много места/времени.
Без `--with-music` аудио нужно резервировать отдельно. Бэкапы содержат приватные
данные аккаунтов и сертификатов: храните их закрыто и отдельно от репозитория.

Восстановление выполняйте в **новом каталоге** того же комплекта. Остановите только
этот Compose-проект (`docker compose --env-file .env --profile public stop`).
Проверьте `manifest.json` и SHA256 `navidrome.sqlite`, скопируйте БД в
`data/navidrome/navidrome.db`, музыку — в `data/music/library`, аватары — в
`data/api`, marker — в `data/bootstrap`. Не накладывайте БД на работающий Navidrome
и не переносите старые `-wal`/`-shm` рядом с восстановленной БД. Владельцем файлов
должен быть выбранный LOCAL_UID/GID. TLS-архив относится к `data/caddy`; при
отсутствии архива Caddy сможет запросить сертификат заново при доступном DNS.
Запустите внутренние службы, проверьте локальный `/ping`, затем публичный Caddy.
Старый каталог и бэкап сохраняйте до проверки аккаунтов, плейлистов и треков.
Скрипты не удаляют исходную библиотеку, контейнеры, тома или резервные копии.

## Перенос из Яндекс Музыки

В клиенте откройте настройки переноса, введите **свой** OAuth-токен Яндекс Музыки
и подтвердите отправку своему серверу. Используйте только музыку, к которой у вас
есть право доступа. Доступность скачивания зависит от аккаунта, подписки и источника.
Токен отправляется по HTTPS отдельно от пароля Navidrome, не возвращается клиенту
и не сохраняется в файлах/БД сервера. После перезапуска API задача становится
`paused_auth`: для продолжения нужно снова явно ввести токен. Аудио и прогресс
при этом сохраняются. Отмена останавливает будущие операции, уже готовые файлы
не удаляет. В очереди одна активная задача на пользователя, один общий worker;
предельная очередь8, история200 задач, до50000 уникальных исходных записей на задачу.

Переносятся понравившиеся треки, свои/сохранённые плейлисты и музыка из сохранённых
альбомов. Аудиокниги, подкасты, шум и записи без подтверждённого типа `music`
исключаются. Недоступные записи учитываются отдельно от исключённых. На явном
«Продолжить» они проверяются снова один раз; повторные сетевые попытки ограничены.
Новые файлы — MP3 в качестве источника `nq`, без перекодирования, с текстовыми тегами.
Для них действуют100MB/20 минут и резерв10GiB. Обложки из источника не копируются.

Одинаковый source ID на этом сервере скачивается один раз для всех пользователей.
Перед пропуском проверяются физический путь, размер и SHA256; одно совпадение
названия/исполнителя не считается доказательством. Общая музыка доступна другим
пользователям сервера. Личные плейлисты создаются **приватными**, отдельно для
каждого импортирующего аккаунта, с исходными названиями, порядком и повторами.
Даже пропущенный готовый аудиофайл включается в личный плейлист. Альбомы не
превращаются в дополнительные списки. Списки с одними исключёнными записями
не создаются; недоступные музыкальные записи отмечаются в счётчике пропусков.

После скачивания задача ждёт индексирования Navidrome (обычно до5 минут), затем
сверяет списки. До этого она не считается завершённой. Проверки индекса идут
раз в30 секунд, максимум20 раз; после ошибки можно продолжить вручную. Имена
сохраняются без служебных ID, в приватном комментарии есть marker восстановления.
Не редактируйте импортируемые плейлисты до завершения переноса. Обнаруженное
ручное изменение состава/свойств останавливает перенос списка без перезаписи.
У native API нет атомарного If-Match: между последней проверкой и заменой остаётся
короткое окно гонки с параллельным сторонним клиентом. После завершения списки
можно свободно редактировать; следующий импорт не затрёт обнаруженные изменения.
Глобальный auto-import M3U остаётся выключенным.

Для миграции старого загрузчика есть **необязательный offline**
`seed-yandex-index.py`. Сначала остановите только API этого комплекта либо
выполните seed до его первого запуска. Navidrome и аудио останавливать не нужно.
Используйте music-only manifest, проверенный `downloads.sqlite3` старого загрузчика
и ту же физическую библиотеку, в которой уже находится `tracks/<id>.*`:

```bash
python3 seed-yandex-index.py --state-root ./data/api --library-root ./data/music/library \
  --legacy-db /path/to/downloads.sqlite3 --manifest /path/to/collection.music-only.json
# Проверьте verifiedSourceIDs/rejected, затем повторите с --apply.
```

Seed проверяет только точные записи ID/путь/размер/SHA256 из старой БД и разрешённого
manifest. Не копирует, не переименовывает и не изменяет аудио; перед записью делает
согласованные приватные бэкапы. При занятом worker-lock отказывается работать.
Ручные файлы без такой доказанной связи не объединяются автоматически. Уже
существующие пользовательские плейлисты seed не изменяет. При иной структуре
папок нужен отдельный план интеграции, а не подмена путей или угадывание названий.

## API и проверка комплекта

Подбор музыки описан в [руководстве волны](RADIO_API.md), управление аккаунтами —
в [API администрирования](ADMIN_API.md).

API профиля: `GET /dedsec/profile/v1/me`, `PUT/DELETE/GET /dedsec/profile/v1/avatar`.
Native JWT проверяется через Navidrome, не только декодируется. `me` возвращает
`userId`, `avatarVersion`, `avatarUrl`, `librarySongCount`; отсутствие аватара —
пустые строки, изображение без аватара —404. PUT/DELETE возвращают200 с `me`.

Совместимость загрузки: POST `/api/auth/login?username=...` с URL-encoded
`X-Password` возвращает native JWT текстом; последующие запросы используют Bearer.
POST `/api/resources?source=Uploads&path=/name.mp3&override=false` принимает сырое
тело. GET `/api/settings/sources` отдаёт `Uploads.usedAlt/total/free` для диска.
Остальные файловые операции API запрещены. Публичной регистрации нет.
Контракт очереди переноса описан в [IMPORT_API.md](IMPORT_API.md).

```bash
python3.12 -m venv .tools/test-venv
.tools/test-venv/bin/pip install --require-hashes --only-binary=:all: -r api/requirements.txt
.tools/test-venv/bin/python -m unittest discover -s tests -v
docker compose --env-file .env.example -f compose.yml config --quiet
```
